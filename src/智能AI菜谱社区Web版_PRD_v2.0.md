# 产品需求文档 (PRD)：智能 AI 菜谱社区 Web 版 (V2.0)

## 1. 文档概述
- **产品名称**: 智能 AI 菜谱社区 (CookAI Connect)
- **版本**: V2.0
- **产品形态**: 响应式 Web 应用（适配 PC 和移动端浏览器，主打移动端体验）
- **核心定位升级**: 本应用将从一个纯粹的“菜谱查询工具”全面升级为“智能工具 + 内容社区”的双擎驱动平台。

## 2. 核心业务定位

### 2.1 工具端 (AI Cooking Engine)
打破传统固定菜谱数据库的局限。用户选择现有食材后，系统直接接入 AI 大语言模型（如 GPT-3.5/4、文心一言、通义千问等主流模型 API），根据食材库存和个性化偏好，动态生成独一无二的创意家常菜谱，实现“所想即所得，所剩即所做”。

### 2.2 社区端 (Foodie Community - 仿小红书体验)
打造高活跃度的美食 UGC（用户生成内容）生态。用户可以发布图文并茂的“笔记”（包含美食图片、烹饪心得、翻车/成功经验），其他用户可进行点赞、收藏和评论，形成从“做菜”到“分享”再到“种草”的社交互动闭环。

---

## 3. 新增核心功能需求说明

### 3.1 AI 智能菜谱生成 (AI Cooking Engine)
在现有的食材选择模块后，增加醒目的“AI 智能生成”选项，作为核心转化路径。

*   **多维参数输入**:
    *   **基础食材**: 沿用或优化现有的食材勾选功能（肉类、蔬菜、海鲜、主食等）。
    *   **口味偏好**: 增加标签化的口味选择（如：无辣不欢、清淡饮食、酸甜可口、减脂餐等）。
    *   **烹饪方式**: 增加烹饪偏好选择（如：清蒸、爆炒、慢炖、空气炸锅、免烤箱等）。
    *   **调料库存**: 允许用户补充当前拥有的关键调料，避免 AI 生成无法实现的步骤。
*   **动态生成机制**:
    *   **云端接入**: 界面调用后端云函数（Cloud Functions）或专门的 AI 服务网关，安全稳定地访问大模型 API。
    *   **流式响应 (Streaming)**: 前端必须支持 Server-Sent Events (SSE) 或 WebSocket，展示 AI 打字机流式生成效果，或辅以设计精美的“厨师正在思考”的加载动画，以大幅降低用户等待焦虑。
*   **生成结果展示**:
    *   **创意菜名**: 吸引人且符合逻辑的菜名。
    *   **精准配比**: 由 AI 根据人数和常见比例估算的食材用量。
    *   **详尽步骤**: 分步骤的详细烹饪指导，甚至包含火候和时间提示。
    *   **视觉参考 (Plus)**: 结合 AI 绘图（如 Midjourney API 或类似服务）生成高颜值的成品参考图，增强用户动手欲望。

### 3.2 小红书风美食社区 (Foodie Community)
构建以视觉为导向的社区首页，采用主流的瀑布流或网格状布局，最大化展示美食图片的诱惑力。

*   **图文笔记发布模块**:
    *   **多图支持**: 支持上传 1-9 张高清图片，提供基础裁剪功能。
    *   **内容创作**: 提供标题（限制字数）和正文（支持段落和简单排版）的填写区域。
    *   **标签系统**: 支持添加和选择热门标签（如 `#今日晚餐`、`#打工人带饭`、`#新手零失败`），用于内容分类和检索。
*   **社交互动系统**:
    *   **点赞**: 支持图片双击点赞动画，以及常规的点赞按钮。
    *   **收藏**: 支持将笔记加入个人的“收藏夹”或“待做清单”。
    *   **评论**: 支持在笔记详情页展开评论区，进行盖楼回复互动。
*   **用户主页 (My Profile)**:
    *   **个人信息**: 头像、昵称、个性签名、获赞与收藏数据统计。
    *   **发布页**: 以网格形式展示自己发布过的所有美食笔记。
    *   **收藏页**: 展示用户收藏的平台菜谱和他人发布的笔记。

## 4. Web 端界面概念设计原则

为实现文档中提到的“清新、现代的 UI 风格”，特制定以下 Web 端概念设计指导原则：

1.  **视觉基调 (Visual Tone)**:
    *   主色调：采用能激发食欲和健康感的清新色彩（如牛油果绿 `#A3C3A0`，或温暖的奶油色 `#FFFBF0` 配合活力橙色点缀）。
    *   风格：采用现代轻拟物或毛玻璃（Glassmorphism）风格，提升整体的呼吸感和高级感。
2.  **布局形态 (Layout)**:
    *   **全响应式设计**: 必须完美适配从宽屏桌面到手机端浏览器的尺寸。
    *   **移动端优先 (Mobile-First)**: 鉴于厨房场景多使用手机，核心交互（如滑动翻页、底部导航栏、大面积点击热区）需优先满足移动端操作习惯。
    *   **瀑布流**: 社区主页采用双列（移动端）或多列（PC端）瀑布流，卡片需进行圆角处理并带有轻微阴影，悬浮时可加入微交互动画。
3.  **核心组件设计**:
    *   **食材选择器**: 采用大图标或精致的矢量插画表示食材，点击状态区分明显。
    *   **AI 魔法按钮**: “Match with AI / AI 智能生成”按钮需采用渐变色或特殊的发光动效，突出其核心地位。

## 5. 后续规划与技术建议
*   **技术栈建议**: 推荐使用 React、Vue.js 或 Next.js 配合 Tailwind CSS 进行快速响应式界面的构建；后端可考虑 Node.js/Go 以更好地处理 AI 接口的高并发流式返回。
*   **审核机制**: 社区内容上线前需考虑接入图片和文本的内容安全审核 API（如鉴黄、涉政过滤）。
